# markdown-style.md — 科研/学习 Markdown 写作规范

本文件规定 markdown-math-writer 产出的 Markdown 文档整体质量要求。公式规范见 `math-syntax.md`，渲染器兼容见 `compatibility.md`。

## 1. 文档结构

- 一个文档一个 `#` 标题；章节用 `##`，小节用 `###`，层级连续递增，不跳级。
- 长文档开头提供目录（或"本文内容"列表）。
- 章节标题简洁、术语准确，不堆砌 emoji。

## 2. 段落与标点

- 中英文混排：中文与英文/数字之间留一个空格（如"质量为 10 kg"），术语和公式保留原文。
- 中文标点用全角（，。；：""），英文/公式上下文用半角。
- 段落不空行分隔句子；段落之间空一行。
- 不在正文滥用 HTML（`<br>`、`<center>` 等）；表格用 Markdown 语法。

## 3. 列表

- 无序列表用 `-`，有序列表用 `1.`，同一列表内混用符号是错误。
- 嵌套列表缩进 2 空格，且前后结构一致。
- 列表项中的公式用行内 `$...$`；整段推导用列表外 display math。

## 4. 表格

- 用 GFM 表格语法，表头与分隔行必须齐全：

  ```markdown
  | 量 | 符号 | 公式 |
  |---|---|---|
  | 能量 | $E$ | $E=mc^2$ |
  ```

- 表格列内容保持简洁；复杂公式移到表格下方单独展示。
- 数值表格注意单位与有效数字；来源列可注明文献/页码。

## 5. 代码块

- fenced code block 必须标注语言：` ```python `、` ```bash `、` ```latex ` 等。
- 代码块中的 `$`、`\` 是字面量，保持原样。
- 代码块用于代码示例；需要渲染的公式禁止放入代码块。

## 6. 公式排版

- 变量、符号、短公式用行内 `$...$`，不单独占行。
- 较长公式、推导、多行方程用 `$$...$$`。
- 公式后紧接符号解释（"其中 $m$ 为质量，$v$ 为速度"）。
- 推导分步骤展示：每一步一个 display math，步与步之间用文字衔接说明变换依据。
- 编号公式：GitHub Markdown 不假定 `\begin{equation}` 存在。优先 Markdown 文本编号 `**(3.1)**` + 独立公式；或 `\tag{...}` 且必须位于 `\end{...}` 之后（`\tag` 在 aligned 内部会导致 KaTeX/GitHub 报错）。

## 7. 科研文档风格

- 简洁、客观、术语保留原文（不强行翻译专业名词）。
- 定义 → 定理/公式 → 解释 → 示例 → 应用 的层次组织。
- 引用文献用 `[1]` 形式并在文末列出；来源可追溯。
- 不确定的内容标注"待确认"，不编造公式或数据。
- 不滥用 emoji 与装饰性符号；标题、正文保持学术风。

## 8. 中文学习笔记补充

- 每章开头写"本章要点"；结尾写"小结"。
- 重点公式用 display math 突出，并解释每个符号含义与适用条件。
- 易错点用「注意」小节或引用块标注。

## 9. 成文检查清单

- [ ] heading 层级合理、无跳级
- [ ] 列表符号统一、缩进一致
- [ ] 表格语法完整（表头/分隔行/对齐）
- [ ] code fence 均标注语言
- [ ] 中文全角标点、中英混排空格
- [ ] 无滥用 HTML / emoji
- [ ] 公式分隔符统一（`$` / `$$`），无 `\(...\)`
- [ ] 公式后解释符号、推导分步骤
- [ ] 术语保留原文
- [ ] 运行 `validate_math.mjs` 通过
