# 添加新桌宠指南

新增一只桌宠 = **新建一个目录 + 表情素材 + `pet_spec.json` + 8 行薄壳**，零引擎改动。通用引擎 `core/pet_engine.py` 由 `pet_spec.json` 驱动，目录放进去就能跑。本指南以新增 `mypet` 为例。

## 步骤清单

### ① 新建桌宠目录

```bash
mkdir -p <库根>/pets/mypet/emotes
```

### ② 复制薄壳 pet.py

```bash
cp <库根>/pets/demo/pet.py <库根>/pets/mypet/pet.py
chmod +x <库根>/pets/mypet/pet.py
```

`pet.py` 就是下面这 8 行样板，所有桌宠逐字节相同，不需要改任何东西：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
import os, sys
ROOT = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
sys.path.insert(0, ROOT)
from core.pet_engine import main
if __name__ == "__main__":
    main(pet_dir=os.path.dirname(os.path.abspath(__file__)))
```

### ③ 准备表情素材（5 个 GIF）

按 `<前缀>_1.gif` 到 `<前缀>_5.gif` 命名，放进 `emotes/`。`<前缀>` 与 `pet_spec.json` 的 `status_icon` 保持一致（见④），例如前缀 `mypet` → `mypet_1.gif` … `mypet_5.gif`。

- 引擎从 `status_icon`（形如 `emotes/mypet_1.gif`）推导出完整命名 `emotes/mypet_<n>.gif`（n 为 `emote_map` 里的编号）
- **命名必须与 `status_icon` 的前缀一致**，否则表情加载不出来
- 没有现成素材？可以仿照 `scripts/generate_demo_emotes.py` 用 PIL 程序生成（该脚本是 demo 桌宠的表情生成器，只依赖 `Image` / `ImageDraw`，可重复运行）

### ④ 写 pet_spec.json

每只桌宠的规格文件，全部字段如下（示例值为 remiel 桌宠的取值）：

| 字段 | 含义 | 示例（remiel） |
|---|---|---|
| `name` | 桌宠名，必须与目录名一致 | `"remiel"` |
| `display_name` | 显示名（状态栏菜单标题等） | `"雷米埃尔"` |
| `emotes_dir` | 表情目录（相对桌宠目录） | `"emotes"` |
| `html` | 网页版文件名（相对桌宠目录，可为空） | `"pet.html"` |
| `state_file` | 状态通道绝对路径，**必须与其他桌宠不同** | `"/tmp/remiel-pet.state"` |
| `bubble_file` | 气泡通道绝对路径，**必须与其他桌宠不同** | `"/tmp/remiel-pet.bubble"` |
| `config_file` | 用户设定文件名 | `".pet-config.json"` |
| `lock_file` | 单实例锁文件名 | `".pet.lock"` |
| `status_icon` | 状态图标路径，同时用于推导表情命名前缀 | `"emotes/remiel_1.gif"` |
| `emote_map` | 状态 → 表情编号（编号落在 1..5 内） | `{"idle":1,"thinking":2,"waiting":3,"running":4,"success":5}` |
| `defaults` | 窗口/气泡默认配置（键与 `.pet-config.json` 的 17 字段对应，另含 `min_width` / `max_width` / `step_ratio`；省略的键回退引擎内置默认） | 见下方示例 |

参考 `pets/demo/pet_spec.json`（完整且最小）照抄一份，改掉高亮的字段即可：

```json
{
  "name": "mypet",
  "display_name": "我的桌宠",
  "emotes_dir": "emotes",
  "html": "pet.html",
  "state_file": "/tmp/mypet-pet.state",
  "bubble_file": "/tmp/mypet-pet.bubble",
  "config_file": ".pet-config.json",
  "lock_file": ".pet.lock",
  "status_icon": "emotes/mypet_1.gif",
  "emote_map": {"idle": 1, "thinking": 2, "waiting": 3, "running": 4, "success": 5},
  "defaults": {"width": 150, "min_width": 90, "max_width": 280, "step_ratio": 1.15, "bubbles": 4, "lifetime": 6, "side": "right", "bubble_border_w": 0, "bubble_border_color": "#c9b8d0", "bubble_font_size": 12, "bubble_text_color": "#3a2b3f", "bubble_bg_color": "#ffffff", "bubble_bg_alpha": 92, "bubble_gap": 2, "bubble_shape": "rect"}
}
```

要点：

- `state_file` / `bubble_file` 是**每只桌宠独立的通道**，写重复了两只桌宠会互相串扰（见「常见问题」）
- `emote_map` 的编号对应 `emotes/` 里的文件编号，超出实际文件范围的表情会缺帧
- `emote_map` 建议包含 `waiting`（3 号表情）：DSH 插件等联动来源会用到该状态，缺了也只是不切表情，不报错
- `defaults` 决定该桌宠的默认大小、气泡数量与样式，可与 remiel 完全不同（demo 就是这么定制的）

> **互动账本自动生成**：摸头 / 喂食 / 亲密度 / 小鱼干 / 自定义名字存在 `pets/<名称>/.pet-profile.json`，引擎自动创建与维护，新桌宠无需准备任何文件。

### ⑤ （可选）pet.html

想有网页版就放一个 `pet.html`（参考 `pets/demo/pet.html` 的极简写法）；不需要就把 `html` 字段留空，状态栏菜单不会显示「打开网页版」。

### ⑥ 切换活动桌宠

```bash
# 先停掉当前桌宠
<库根>/scripts/petctl.sh remiel stop

# 把 active 改成新桌宠名
# 编辑 ~/.config/desktop-pets.json（或 ~/.config/opencode/desktop-pets.json）
#   →  {"root": "/Users/yucong/Documents/Deepseek Harness/dsh-skills-plugins/projects/desktop-pets", "active": "mypet"}
```

`~/.config/desktop-pets.json`（优先）或 `~/.config/opencode/desktop-pets.json` 的 `active` 字段决定「活动桌宠」：opencode 插件、DSH 插件、`petctl.sh` 不带名字的调用、LaunchAgent 自启都指向它。改完重启桌宠即生效。

### ⑦ 启动验证

```bash
<库根>/scripts/petctl.sh mypet start
```

## 验收清单

全部通过即为达标：

| 检查项 | 方法 |
|---|---|
| 启动日志与右下角停靠 | `tail <库根>/pets/mypet/pet.log` 出现 `[pet] 启动 ... pos=(x,y)`，窗口出现在屏幕右下角 |
| 状态切换走各自通道 | `echo thinking > /tmp/mypet-pet.state`，表情切到 thinking；其余桌宠（remiel/demo）表情不变 |
| 气泡 | `echo "run\|Bash\|测试" > /tmp/mypet-pet.bubble`，头顶弹泡 |
| 右键菜单 | 右键各项可用，缩放 / 气泡样式改动即时生效 |
| 设定保存 | 调整后 `pets/mypet/.pet-config.json` 出现且记录新值 |
| 多桌宠并存不串扰 | 新桌宠与 remiel（或 demo）同时运行，通道、锁、配置各自独立，互不影响 |

## 常见问题

**表情不显示**：表情文件命名与 `status_icon` 前缀不一致（比如 `status_icon` 填 `emotes/mypet_1.gif`，但文件叫 `m_1.gif`），或 `emote_map` 引用了不存在的编号。对照④的命名约定检查。

**通道串扰**：两只桌宠的 `state_file` / `bubble_file` 写成了同一个 `/tmp` 文件，导致互相抢表情。把每只桌宠的通道改成独立路径即可。

**单实例锁**：快速连续重启同一只桌宠可能撞上 `.pet.lock`，新进程会静默退出（日志为空，容易被误判为「没起来」）。`pkill` 后等约 2 秒再 `start`。

**opencode 不跟新桌宠**：插件只在启动时读一次 `desktop-pets.json`。切换 `active` 后需要重启桌宠，并**完全重启 opencode** 让插件重新读取配置（用 `ls -l /tmp/desktop-pets-plugin.loaded` 确认插件已加载）。
